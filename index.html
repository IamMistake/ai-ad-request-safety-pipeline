Request Fraud & Moderation Detection

A streaming pipeline that detects ad request fraud and moderates unsafe content in real-time using Apache Kafka, Flink, and Spark.

The Problem

AI-powered platforms are increasingly injecting sponsored content into their responses. This creates a new attack surface: bad actors can craft requests that exploit the ad injection mechanism — committing fraud, gaming the system, or injecting unsafe content.

Ad Fraud

Burst traffic, bot-generated requests, and IP/proxy churn designed to extract value from the monetization layer.

Unsafe Content

Manipulative, toxic, or policy-violating prompts that should never reach the ad injection stage.

Real-Time Scale

Fraud decisions must happen in-stream with low latency — batch analysis after the fact is too late.

Architecture

The pipeline evaluates every request through multiple defense layers before it reaches ad injection. Flink provides real-time analysis, moderation checks content safety, and Spark trains better models offline.

How It Works

A request’s journey through the pipeline — step by step.

1

Request Simulator

Generates synthetic ad request traffic from real conversation data (WildChat dataset, 175k prompts). Each request includes a prompt, session context, user agent, IP, country, and ASN. Supports normal and fraud traffic profiles.

{
  "event_time": "2023-04-10T00:01:08+00:00",
  "req_id": "5e87cd8f53dff5e7",
  "prompt": "Write a very long...",
  "language": "English",
  "request_context": {
    "session_id": "conv-id",
    "user_agent": "Mozilla/5.0",
    "user_ip": "158.37.13.4"
  },
  "optional_context": {
    "country": "NO",
    "asn": 64512
  },
  "publisher_id": "conv-id"
}
2

Kafka Event Stream

Requests flow through five Kafka topics: requests.raw (ingress), requests.sus (suspicious), requests.clean (fraud-clean), requests.fraud (blocked), and ad.injection (approved). Kafka decouples all pipeline stages.

3

Flink Fraud Detection

Consumes requests.raw, assigns event-time watermarks, then keys the stream through three stateful detectors: User → Session → Publisher. Each detector applies rules and accumulates a fraud score.

score < 0.5        → requests.clean (pass through)
0.5 ≤ score < 0.8 → requests.sus   (RFC scoring)
score ≥ 0.8        → requests.fraud (blocked)
4

RFC Scoring Planned

Consumes requests.sus, applies the Spark-trained RandomForest model to score suspicious requests. Cleared requests go to requests.clean; confirmed fraud goes to requests.fraud.

5

Moderation

Analyzes prompt content for safety. Two modes: mock (rule-based, great for local dev) and OpenAI (calls the OpenAI Moderation API). Prompt caching via SHA256 hash avoids redundant calls.

Mock mode:  keyword patterns + normalization checks
OpenAI:     omni-moderation-latest API
Clean → ad.injection  |  Unsafe → requests.fraud
6

Spark Analytics & ML Training

Exports historical logs from Kafka, runs batch analytics, and trains a RandomForestClassifier on features like scam keyword presence, ASN, and prior fraud score. Writes risk rollups and model artifacts for the RFC scoring service.

Fraud Detection

Flink evaluates each request through 14 rules across three scopes. Rules are scored incrementally; the final score determines whether the request is clean, suspicious, or fraud.

Moderation

The moderation service analyzes prompt content for safety before forwarding to ad injection. It supports two provider modes.

Rule-Based Local Moderation

Default mode for local development. Uses keyword patterns, normalization, and TF-IDF similarity to detect unsafe prompts. No external API calls — fast and repeatable.

# No API key needed
MODERATION_PROVIDER=mock

# Uses ModerationAnalyzer with keyword rules
# and TF-IDF gating against reference corpus

OpenAI Moderation API

Calls the OpenAI Moderation API (omni-moderation-latest) for more accurate content safety checks. Requires an API key. Prompt caching avoids redundant calls.

# Set in .env
MODERATION_PROVIDER=openai
OPENAI_API_KEY=sk-...
OPENAI_MODERATION_MODEL=omni-moderation-latest

Moderation Flow

requests.clean → ModerationClient.analyze(prompt)
                 |- Check cache (SHA256 normalized prompt)
                 |- Mock/OpenAI analysis
                 '- Route result
                    |- Clean → ad.injection
                    '- Unsafe → requests.fraud

Spark Analytics & ML

Spark processes historical export data to train fraud detection models and compute risk profiles.

Feature Engineering

Three features for the RandomForest model:

  • contains_scam — Regex match against scam keywords
  • asn — Autonomous System Number (network risk)
  • fraud_score_feature — Prior Flink fraud score

Risk Rollups

  • ip_risk_scores.json — Per-IP metrics
  • publisher_risk_scores.json — Per-publisher
  • asn_risk_scores.json — Per-ASN risk
  • session_risk_scores.json — Per-session fraud

Model Artifacts

  • fraud_model.pkl — Serialized RandomForest
  • model_metrics.json — Accuracy + report
  • feature_columns.json — Feature schema

Data & Datasets

The pipeline uses real conversation data for realistic traffic simulation and offline model training.

WildChat Source

175k real GPT conversations from April 2023. Provides prompt text, moderation labels, language (30+), and unique conversation IDs used as session/publisher identifiers.

175,238 rows across 2 shards

GeoLite2 Source

MaxMind GeoIP databases for IP-to-location resolution. ~92% of random public IPv4s resolve to a country. Used for country-hop detection and language/country mismatch rules.

City + Country databases

Traffic Profiles

Two traffic profiles: normal (realistic behavior) and fraud (bursts, bot patterns, suspicious IP churn).

Getting Started

Run the full pipeline locally in a few steps.

Prerequisites
# Python 3.10+
# Docker + Docker Compose
1. Start infrastructure
docker-compose up -d
2. Install dependencies
pip install -r requirements.txt
3. Transform dataset
python scripts/transform_wildchat_user_prompts.py
4. Run the pipeline
# Terminal 1: Request simulator
python kafka/producers/request_simulator.py

# Terminal 2: Flink fraud detection
python flink_service/fraud_detection.py

# Terminal 3: Moderation consumer
python pipeline_consumers/moderation_consumer.py

# Terminal 4: Debug consumer
python test_consumer.py
5. Run pipeline tests
./scripts/test_full_pipeline.sh
./scripts/test_fraud_block_flow.sh
./scripts/test_moderation_block_flow.sh
6. Spark training
# Export historical logs
python spark_service/historical_exporter.py \
  --from-beginning --idle-seconds 30

# Run training
python spark_service/spark_training.py
